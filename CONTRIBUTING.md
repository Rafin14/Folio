# Contributing

Read [BUILDING.md](BUILDING.md), [testing notes](docs/TESTING.md) and the license first. Keep changes focused and extend existing repositories, workers, export/print pipelines and model handling instead of creating competing implementations.

Use nonsensitive synthetic samples in tests and issues. Never commit local configuration, signing keys, credentials, app databases, device logs or personal images. Model replacements require provenance, compatible decoding and applicable notices.

Run build, unit tests and lint; run relevant Android integration/UI tests on a dedicated emulator/device. Explain the problem, behavior change, actual validation and remaining limitations in a pull request. Distinguish emulator coverage from physical camera, accelerator, printing and live Drive checks.

For visual changes, provide safe application screenshots in light/dark themes and check compact screens/large text. Preserve retained originals, Room migration compatibility, durable work and account/ownership boundaries.
