# Security reporting

Do not post private documents, OAuth tokens, client secrets, signing keys, account emails or unredacted logs in public issues.

Report suspected vulnerabilities privately using the public contact method supplied by the project owner's repository/profile, if available. If the eventual GitHub repository enables private vulnerability reporting, use its Security tab. No private email address or unverified reporting URL is provided in this source package.

Include the app version, Android version, a concise description, impact and reproduction steps using nonsensitive sample data. Avoid attaching credentials or live account identifiers. There is no stated response-time guarantee or supported-version policy for this preview.

Keep local SDK/OAuth settings and signing credentials out of version control. Use your own OAuth clients for source builds; a Web client secret is neither required nor used. Never run destructive cloud verification on a real account without explicit permission and recoverable test data.
